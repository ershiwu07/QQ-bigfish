# QQ 大肥鱼机器人（DeepSeek Harness × NapCat）

一个用**大肥鱼 / 鲸鱼娘**人设说话、自动回复 QQ 消息的机器人。

- **大脑**：DeepSeek Harness（DSH）的 SDK 长驻运行时，模型 `deepseek-flash`
- **人设**：`config/persona.md`（可随意改，改完重启生效）
- **接入**：OneBot v11 协议（正向 WebSocket）→ [NapCat](https://napneko.github.io/)
- **记忆**：每个 QQ 会话（每个群 / 每个好友）各自一条 DSH 持久会话，天然多轮记忆
- **安全**：DSH 侧的工具（shell / 文件）**已全部关闭**，QQ 消息只能让它说话，不能让它在你电脑上执行任何东西

---

## 现在能做什么（v1 范围）

| 能力 | 状态 |
|---|---|
| 私聊自动回复 | ✅ 默认全部回复 |
| **群聊自主参与** | ✅ 群里每条消息都会**交给它自己判断**该不该开口，不需要 @ 它也不用喊关键词 |
| **自主判断分寸** | ✅ 觉得不该插话就静默（`[NO_REPLY]`）；技术问题、有人问它擅长的事、明显说错的话、冷场，它会接 |
| **长期记忆** | ✅ 它会自己把值得记的事（谁是谁、在做什么、群里的约定）写进记忆，之后一直带着 |
| **从群聊里持续学习** | ✅ 每 25 条消息自动提炼一次：游戏/动画/角色、群里自己的黑话术语、成员称呼习惯。**它不说话时也在学** |
| **跨重启记忆** | ✅ `state/memory.json`，重启后照样记得你们聊过什么 |
| **防抢话** | ✅ 它说完话会安静 20 秒让别人说；被 @ 则不受此限（叫它必须应） |
| 拟人化节奏（停顿后回复、长回复分条发） | ✅ |
| 防刷屏（限流 + 去重 + 冷却） | ✅ |
| 纯文字理解 | ✅ |
| **识图** | ✅ **真的把图片下载下来喂给模型**（`deepseek-flash` 支持图片输入）。群里所有图都会看一眼，私聊的也会 |
| **QQ 内置表情 / 大表情 / 拍一拍** | ✅ 表情翻译成 `[偷笑]`／`[大表情:大怨种]`；拍一拍会转成一条消息让她能回应 |
| 读群里的链接 / 分享卡片 | ✅ 能拿到标题和简介（转发的视频、文章都在这一类） |
| **联网搜索 / 看网页 / 天气** | ✅ **只读工具**：`web_search` + `web_fetch`。问天气、问版本号、问新闻，她会真去查（见下文「只读联网」） |
| 看视频画面 | ❌ 模型不接收视频。抽帧方案评估过：要装 ffmpeg、要下整段视频、抽几帧也说不清内容，**性价比太低，不做** |
| 在本机执行命令 / 读写文件 | ❌ **永远不做**——QQ 消息是外部输入，给她 shell 等于把电脑交给群里任何人 |
| 主动挑起话题 / 定时任务 | ❌ 还没做（见文末路线图） |

> 关于「免打扰群」：因为现在跑的是**小号**，本来就不在你的群里，所以 `mutedGroups` 留空即可。
> 这个功能仍然保留——将来某个群嫌它吵，把群号填进去就闭嘴了。

## 快速开始

### 0. 前置条件

- **Node.js ≥ 22**（代码用了内置的全局 `WebSocket`，Node 20 跑不起来）
- **DeepSeek API Key**（[platform.deepseek.com](https://platform.deepseek.com)，建议给机器人单独建一个）
- **一个 QQ 小号**（强烈建议，原因见「风险」一节）

> 第 1 步**不需要 QQ**，可以先把"大脑"跑通；**第 2 步开始才涉及 QQ**。

### 1. 拿到 DSH + 填 Key + 跑一次自检

本项目**不自带** DSH，它调用 `dsh --profile sdk-minimal` 启动运行时。二选一：

```powershell
npm i @deepseek-ai/dsh                 # ① 装在项目里（推荐，版本可控；约 500 个包，两三分钟）
npx --yes @deepseek-ai/dsh --version   # ② 或者让它进 npx 缓存就行
```

（两种都能被自动找到。装在别处的怪位置就用环境变量 `DSH_BIN` 指过去。）

> npm 可能会提示 `install-scripts ... not yet covered by allowScripts`。**实测可以忽略**——
> 本项目只用到 DSH 的 SDK 运行时，不依赖那几个包的原生构建脚本。

然后填 Key：

```powershell
copy .env.example .env      # Linux/macOS 用 cp
notepad .env                # 把 DEEPSEEK_API_KEY= 后面换成你的 Key（不要加引号、不要留空格）
```

**现在先跑一次自检**——它会检查配置、人设、DSH 握手、API Key，全程不花 token：

```powershell
node src/index.mjs --check
```

```text
首次运行：已从模板创建配置文件
  config\bot.config.example.json  →  config\bot.config.json
  ★ 请打开它，把 onebot.expectSelfId 填成你的机器人 QQ 号，然后重新启动。
...
[INFO] API Key 自检通过。
[INFO] 自检通过：配置、人设、DSH 运行时握手、API Key 全部正常。
```

> `config/bot.config.json` **就是这一步生成的**（第 4 步要编辑它，所以别跳过这里）。
> 如果这里就报 `API Key 无效（HTTP 401）`，先去平台确认 Key；**这一步不涉及 QQ，出问题一定在 Key 或 DSH。**

### 2. 装 NapCat 并登录小号

按 [NapCat 官方文档](https://napneko.github.io/) 安装，用一个**小号**登录。

> NapCat 是非官方协议实现，登录主号有被腾讯风控/冻结的风险。请用小号。

### 3. 在 NapCat 里开「正向 WebSocket」

NapCat 的 **网络配置 → 新建 → WebSocket 服务端**：

| 项 | 值 |
|---|---|
| 主机 | `127.0.0.1` |
| 端口 | `3001` |
| 消息格式 | `array` 或 `string` 都支持 |
| Token | 可留空；若设置了，请填到配置里的 `onebot.accessToken` |

（本项目是「主动去连 NapCat」，所以要用**正向/服务端** WebSocket。）

### 4. 填上机器人自己的 QQ 号

编辑第 1 步已经生成好的 `config/bot.config.json`：

```json
"onebot": { "expectSelfId": "你的机器人小号QQ" }
```

填了它，万一 NapCat 登错号（比如手滑登上主号），机器人会**拒绝回复并报警**。
（这个文件已被 `.gitignore` 排除，你的号不会进仓库。）

### 5. 启动

```powershell
node src/index.mjs          # 前台运行，Ctrl+C 退出
npm start                   # 等价
```

Windows 上也可以双击 **`start.cmd`**（`.cmd` 不受 PowerShell 脚本策略限制，且结尾有 `pause`，出错不会闪退）。

启动成功的标志是这两行：

```text
[INFO] [bot:onebot] 登录号已确认：你的号（与 expectSelfId 一致）
[INFO] [bot] 机器人已启动，等待消息…（Ctrl+C 退出）
```

### 6.（可选）免打扰群、开机自启

**免打扰群**：编辑 `config/bot.config.json`：

```json
"trigger": {
  "mutedGroups": [20001, 20002],
  ...
}
```

`mutedGroups` 里的群号**一条消息都不会回**（哪怕 @ 它）。
群号在 QQ 群的「群资料」里能看到，也可以在机器人日志里看到（`收到 群 20001 …`）。

> ⚠️ QQ 客户端的「消息免打扰」是**本地设置**，机器人（OneBot 协议）读不到，
> 所以必须像上面这样手填一份名单。这是协议限制，不是本项目的偷懒。

**开机自启（Windows）**：计划任务指向 `run-hidden.vbs` 即可（它自己推导项目目录，换路径不用改）。
仓库里的 `start.cmd` / `stop.cmd` / `pause.cmd` / `resume.cmd` / `status.cmd` 都是 Windows 快捷方式；
**其它系统直接跑 `node src/index.mjs`**，功能没有任何区别。

> ⚠️ **如果 `.\start.ps1` 报「因为在此系统上禁止运行脚本」**（`UnauthorizedAccess`）：
> 这是 Windows 默认的 PowerShell 执行策略在拦截 `.ps1`，跟本项目无关。三种解法任选：
> 1. 改用上面的 `node src/index.mjs` 或 `start.cmd`（推荐）
> 2. 临时绕过：`powershell -ExecutionPolicy Bypass -File .\start.ps1`
> 3. 永久放开当前用户：`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`（会改系统设置，需自行判断）

日志会打印连接状态、收到的消息和回复内容，同时写入 `logs/bot.log`。
**启动成功的标志**是看到这一行：

```text
[INFO] [bot] 机器人已启动，等待消息…（Ctrl+C 退出）
```

**这个窗口要一直开着**（可以最小化）。停止就按 `Ctrl+C`。

## 配置详解（`config/bot.config.json`）

### `onebot` —— 怎么连 QQ

| 字段 | 默认 | 说明 |
|---|---|---|
| `mode` | `forward` | 只支持 `forward`（本项目主动连 NapCat） |
| `url` | `ws://127.0.0.1:3001` | NapCat 正向 WebSocket 地址 |
| `accessToken` | `""` | 与 NapCat 里设置的 Token 一致；没设就留空 |
| `expectSelfId` | `""` | **强烈建议填小号 QQ 号**。填了之后，若 NapCat 登录的不是它，机器人一条都不回并报警——防「快速登录」手滑登上主号 |

### `dsh` —— 大脑

| 字段 | 默认 | 说明 |
|---|---|---|
| `bin` | `""` | 留空则自动在 npx 缓存/全局 npm 里找 dsh；找不到就填 `...\@deepseek-ai\dsh\lib\bin.js` 绝对路径，或设环境变量 `DSH_BIN` |
| `dshHome` | `dsh-home` | 本项目专用的 DSH_HOME（与你的 `~/.dsh` 完全隔离） |
| `provider` / `model` | `deepseek-official` / `deepseek-flash` | 也可用 `deepseek-v4-pro` |
| `reasoningEffort` | `low` | `low` 最快；`high`/`max` 更聪明但更慢更贵 |
| `maxTokens` | `1200` | 单次回复上限，防止它写小作文 |
| `turnTimeoutMs` | `120000` | 一轮超时（超时会重启运行时并回兜底话术） |
| `sessionRotateTurns` | `300` | 一个会话聊满这么多轮就换新会话（控制上下文长度与成本，聊天记忆不受影响） |
| `pruneStaleSessions` | `true` | 启动时清理上一次运行遗留的、已无法接管的 DSH 会话（最近 10 分钟内写过的会跳过） |
| `personaFile` | `config/persona.md` | 人设文件 |

### `memory` —— 大肥鱼的记性

| 字段 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 关掉就变成「重启即失忆」 |
| `file` | `state/memory.json` | 记忆文件。删掉它 = 让大肥鱼忘掉所有群和好友 |
| `maxChats` | `2000` | 最多记多少个会话（超出按最久未活动淘汰） |
| `maxPerChat` | `160` | 每个会话最多留多少条消息流水（超出丢最早的）。**它不影响每轮提示词大小**——提示词只取 `context.recentXxxMessages` 条，还有 `context.maxChars` 兜着 |
| `maxNotesPerChat` | `80` | 每个会话最多留多少条**长期记忆事实**（它自己提炼的那些） |
| `maxFactsPerMember` | `40` | **每个群成员**最多留多少条关于他的记忆 |

> 想看看它记住了什么？直接打开 `state/memory.json`，`notes` 是会话级记忆，`members` 是按人存的档案。
> 想让它忘掉某件事，删掉对应的那条即可（改完不用重启，下次读写会生效）。

### 群成员档案：她怎么"记住群里不同的人"

光有聊天流水，她只知道"刚才这几句是谁说的"；档案让她知道**这是谁、他喜欢什么、上次聊到哪**。

```jsonc
"members": {
  "10003": {
    "c": "老陆",              // 群名片
    "n": "老陆",              // QQ 昵称
    "cnt": 37,                  // 在群里说过多少次话（自动统计，不花模型的钱）
    "last": 1759231000000,      // 最后发言时间
    "f": [ { "t": "喜欢星穹铁道，习惯半夜在线" } ]   // 关于他的记忆
  }
}
```

三条来源，互相补：

| 来源 | 怎么来 | 花不花模型的钱 |
|---|---|---|
| **名字/次数/最后发言** | 每条消息自动统计（`touchMember`） | 不花 |
| **关于他的事实** | 学习时让模型写成 `[记忆] 名字 :: 事实`，落库时翻译成 QQ 号 | 花（和原本的学习同一次调用） |
| **一次性打底** | `node tools/seed-members.mjs` 拉 NapCat 的群成员名单，并把已有记忆按人重新归档 | 不花 |

这些会作为【正在说话的人】和【这个群里的常客】注入提示词，所以别人一开口她就认得：

```text
【正在说话的人】老陆（QQ 10003）
　在群里说过 37 次话，上一次说话约 1 小时前
　你记得关于他的事：
　· 喜欢星穹铁道，习惯半夜在线
【这个群里的常客】老陆(现在说话这个)、小雪、阿澈、杰瑞
```

名字认不出来时，那条记忆会退回会话级存储（不会丢，也不会硬塞给某个人）。

### `trigger` —— 什么情况回

| 字段 | 默认 | 说明 |
|---|---|---|
| `private` | `all` | 私聊策略：`all` / `whitelist` / `none` |
| `group` | `all` | 群策略：**`all`＝每条都交给它判断**（推荐，配合 `selfDecide`）；也可退回 `at_or_keyword` / `at_only` / `whitelist` |
| `selfDecide` | `true` | **它自己决定说不说**。觉得不该插话就输出 `[NO_REPLY]`，群里什么都不会收到 |
| **`replyChance`** | `1` | **活跃度旋钮**：`1`＝每条群消息都判断（最聪明）；`0.5`＝一半消息才判断（省一半钱）；`0`＝群里只在被 @ 或命中关键词时才动。**被 @ 和关键词不受它影响，永远必应** |
| `keywords` | `["大肥鱼","肥鱼","鲸鱼娘",…]` | 命中即视为「点名」，一定会回 |
| `mutedGroups` | `[]` | 免打扰群，一条都不回（现在用不上，留着备用） |
| `groupWhitelist` | `[]` | 非空时，只有名单里的群才可能被回复 |
| `alwaysReplyGroups` | `[]` | 这些群里的消息一律交给模型（等同 `group: all` 的单群版本） |
| `privateWhitelist` / `privateBlocklist` | `[]` | 私聊白/黑名单 |
| `ignoreAtAll` | `false` | `true` 表示连 @全体成员 也不回 |
| `replyToEmptyAt` | `true` | 单独 @ 它但没打字时也回一句（相当于喊它一声）；@ 的同时只发了图则仍不回 |
| `ignoreSelf` | `true` | 不回复自己发的消息 |

### `limits` —— 防封号 / 防刷屏

| 字段 | 默认 | 说明 |
|---|---|---|
| **`minIntervalPerChatMs`** | `2500` | **非指名**消息之间的最小间隔（防抢话） |
| **`afterReplyCooldownMs`** | `20000` | 它说完话后，**非指名**消息安静一会儿。**指名不受此限** |
| **`directedGapMs`** | `1200` | **指名**连续提问时，两条回答之间的人工间隔 |
| **`maxDirectedPerMinute`** | `12` | **指名**回复的硬上限（防有人刷它）；这是防止滥用的兜底，正常聊天碰不到 |
| **`maxParkedPerChat`** | `3` | 指名消息的排队上限。超出时丢最老的——但它已经在最新那条的上下文快照里，会被一起答掉，**不算真丢** |
| `maxRepliesPerChatPerMinute` | `8` | **非指名**单会话每分钟上限 |
| `maxRepliesPerChatPerHour` | `60` | **非指名**单会话每小时上限 |
| `globalMaxRepliesPerMinute` | `30` | 全机器人每分钟上限（指名与非指名共用） |
| `keywordCooldownMs` | `60000` | 关键词触发的冷却（防有人刷关键词） |
| `dedupeWindowMs` | `120000` | 同一条消息去重窗口（防断线重推重复回复） |

> 一句话记法：**`minInterval` / `afterReplyCooldown` / `maxRepliesPer*` 管的是"它自己想不想插话"，
> `directedGap` / `maxDirectedPerMinute` 管的是"别人叫它时它还嘴的频率"。**
> 活跃度可以调，但**指名必须应**这条不该动。

> 不建议调得比默认更激进。QQ 对高频自动回复非常敏感。

### `learning` —— 从群聊里学习

| 字段 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 关掉就只剩「回复时顺手记」那条路，学习速度会慢很多 |
| `everyMessages` | `25` | 每多少条群消息提炼一次。调小＝学得快但费钱；调大＝省钱但学得慢 |
| `maxMessagesPerDigest` | `30` | 每次提炼交给模型多少条聊天记录 |

> **省钱的组合**：`trigger.replyChance: 0.5` + `learning.everyMessages: 25`。
> 前者让它只对一半消息做"要不要说话"的判断，后者让学习不依赖说话——总调用量大概是"每条都判断"的三分之一，而学习效果反而更好。

### `images` —— 识图

| 字段 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 关掉就退回「只说不看」 |
| **`alwaysLook`** | `true` | **群里所有图一律看一眼**，跟 @ 不 @、跟活跃度骰子都无关（不省这个钱）。看归看，说不说仍由她自己判断 |
| `considerAmbient` | `true` | `alwaysLook` 关掉后的退路：非指名的图走活跃度骰子「随缘看看」 |
| `lookbackMs` | `300000` | **「先发图、再问这是什么」**：后一条消息本身没图时，往回找最近一张没用过的图（默认 5 分钟） |
| `retry` | `1` | 取图失败重试次数。腾讯 CDN 偶发抽风，不重试就会「有的图能看、有的看不到」 |
| `maxPerMessage` | `3` | 一条消息最多看几张图 |
| `maxBytes` | `12582912` | 单张图片原始体积上限（12 MiB）。附件库还会再缩放到 ≤4 MiB 才发给模型 |
| `pruneKeepDays` | `7` | 启动时自动删掉这么多天没动过的图片附件；设 `0` 关闭 |
| `timeoutMs` | `15000` | 下载图片的超时 |

> **同一张图只会喂一次**：图片进了 DSH 会话，后续轮次本来就看得到；再附一遍只会
> 重新下载、重新分析，又慢又费钱（群里那句"花我token是吧"就是这个）。所以喂过就标记，
> 不再重复附上。

### `owner` —— **只管权限，不参与对话**

| 字段 | 默认 | 说明 |
|---|---|---|
| `userId` | 空 | QQ 号。**只有这个号说"静音／恢复"才生效**。留空则谁都能暂停她 |
| `name` / `aliases` | 空 | 只用来在日志和状态里显示，**不会进提示词** |
| `note` | 空 | 同上，不参与对话 |

**这里踩过一个坑，值得写下来**：最早这一节叫「养她的人」，提示词里会一直告诉她
「这个人是谁、这条就是他发的、可以更黏一点」。结果是**她对那个号明显更亲、对别人收着**，
而需求其实是「对所有给她发消息的人同等对待」。

所以现在：

- **亲近是她的默认性格**（写在 `config/persona.md` 里），不由"发消息的人是谁"决定；
- `owner` 退化成**纯权限配置**，只在判定"静音／恢复"这类管理指令时用到；
- 有 4 项自动断言盯着这件事（见 `tools/test-burst-queue.mjs` 第 8 节），
  其中一条是「张三和李四发同样的话，给她的提示只差名字」。

### `context` —— 给它多少前文

`recentGroupMessages` / `recentPrivateMessages` 决定喂多少条最近消息当背景，
`maxChars` 是上下文总字符上限。设 `0` 就是不带上下文。

### `output` —— 像真人打字

`typingDelayMinMs/MaxMs`：回复前随机停顿。
`maxCharsPerMessage` / `maxSegments`：长回复切成几条发（默认最多 3 条、每条 400 字）。

### `fallback` —— 出错了说什么

`onTimeout`：模型超时时的兜底话术（默认「……脑子卡了一下，你再说一遍？」）。
`onError`：其他错误的兜底话术，默认空字符串 = 不回复。

## 它是怎么「自己判断该不该开口」的

这是它和普通「关键词机器人」的本质区别。每来一条群消息，它拿到的是这样一段：

```text
【场景】QQ 群「示例群」（群号 20001）
【你记得的事】· 群主是阿澈    · 群里主要聊 AI 和硬件
【最近消息】
阿澈: 新买的显卡到了
小明: 多少钱
【最新消息】
小明: 这个接口一直 502，日志里啥都没有
```

然后它按人设里的分寸规则自己决定：

- **该说**：有人问问题、聊到它懂的东西、有人明显说错了、冷场了、它有能补充的信息
- **不该说**：别人的私事、约时间地点、互相寒暄、纯灌水（哈哈哈 / +1 / 表情）、它刚说完话还在等别人回应

不该说时它只输出 `[NO_REPLY]`，**群里什么都不会收到**（不会有"正在输入"，也不会有空消息）。

### 实测校准

`node tools/probe-group-judgment.mjs` 用 7 个典型场景跑出来的结果：

| 群里的消息 | 它的判断 |
|---|---|
| 接口一直 502，日志啥都没有 | **说话**：指向网关层日志，列了三个常见原因 |
| 哈哈哈哈 | 沉默 |
| 有没有人知道 token 怎么算钱 | **说话**：输入输出分开计费、中英文字数换算 |
| 你几点到？我在楼下等你 | 沉默 |
| DeepSeek 不是开源的嘛 | **说话**：温和纠正「权重开源 ≠ 服务无条款」 |
| 今天好困啊 | **说话**：「显卡装到半夜了吧」← 结合了上文聊的显卡 |
| 那个大肥鱼机器人还在群里吗 | **说话**，并顺手记下「群主新买了张三千多的显卡」 |

7 个场景开口 5 次，而两个真正该沉默的（纯灌水、别人的私事）都准确沉默了。

### 聊开了、一串问题砸过来的时候

群里常常冷半天，然后突然聊开，一下子问它好几件事。**这是最容易翻车的地方**，所以规则分成了两类：

| | 谁属于这一类 | 怎么处理 |
|---|---|---|
| **指名** | 群里 @ 它、消息命中关键词、私聊 | **绝不丢弃**。进队列，**同一批合并成一次回答**；两条回答之间隔 `directedGapMs`（1.2 秒） |
| **非指名** | 群里没点它的闲聊（`group: all` 时会交给它判断） | 照旧受最小间隔、冷场间隔、每分钟条数限制；拥挤时直接放弃这次 |

**为什么必须分开**：旧版把这两类用同一套限流。结果是——第一句回答还没发出时，后面几句一起涌向模型各回一条（刷屏）；等第一句记进限流后，**紧接着问它的正经问题反而被当成"太频繁"丢掉**，表现就是"聊开了它反而接不上"。

**上下文标记**：记忆里会给每条消息记一个"是不是冲着它说的"标记，提示词里渲染成 `阿澈（@你）: 那个bug咋回事`，并且当它发现有连着几条是问它的，会明确提示：

```text
【注意】上面【最近消息】里标着（@你）的还有 3 条，是连着问你的，你还没答。
请在**这一条回复里把它们一起答掉**：不要分成好几条发，也不要只答最后一句。
```

实测（`node tools/test-burst-queue.mjs`，用假模型跑，不花钱）：

```text
连问 4 句（都 @ 它） → 4 句全部答上，但只发出 2 条回复（合并了），模型调用 2 次
逐句问 3 句          → 3 句全答上（旧版第 2、3 句会被限流丢掉）
非指名闲聊           → 仍然被最小间隔拦住（防抢话没丢）
被 @ 时              → 即使刚说完话也必应
```

### 想调活跃度

| 你想要的 | 怎么改 |
|---|---|
| **更活跃**（几乎每条都想插一句） | 把 `config/persona.md` 里「倾向保守：群里十条消息你接一条就够了」改成「五条接一条」，并把 `limits.afterReplyCooldownMs` 调小（如 `8000`） |
| **更安静** | `trigger.replyChance` 调到 `0.3`，或 `afterReplyCooldownMs` 调到 `60000` |
| **完全回到「不喊不出声」** | `trigger.group` 改回 `at_or_keyword`，`selfDecide` 改 `false` |
| **只让它听、完全不说话** | 把群号填进 `trigger.mutedGroups` |

> 被 @ 和命中关键词**永远不受活跃度影响**——叫它必须应。这是刻意设计的：活跃度只用来控制"它自己想不想说"，不该用来决定"别人叫它它装没听见"。

### 长期记忆是怎么长出来的（两条路）

**路①：它自己顺手记。** 在回复的最后写一行 `[记忆] 一句话事实`（这行**不会发出去**）。
关键是：**即使它选择沉默（`[NO_REPLY]`），也可以写 `[记忆]`** —— 沉默不等于不能记住东西。

**路②：定期提炼。** 每 `learning.everyMessages` 条群消息（默认 25），自动跑一次提炼任务：
把最近 30 条聊天记录 + 已有记忆一起交给模型，只要求它输出新的 `[记忆]` 行。

这条路是必需的：自主判断模式下它大多数消息都沉默，**只靠"回复时顺手记"的话它几乎学不到东西**。
而且它比"每条都判断"便宜得多——25 条消息才一次调用。

实测（`node tools/probe-learning.mjs group:20001`，用真实群聊记录）：

```text
提炼出 3 条新知识：
· 群里说的"酒馆"是现成的开源软件，装上接 API 就能跑，不用自己开发
· 阿澈认为 DSF API 算便宜的，他的项目目前花了他约 4 块钱
· 杰瑞有个同学在 80 人大群里用酒馆玩了一下午，花了三块多
```

> 群自己的黑话、术语、称呼习惯就是这么长出来的。它还会知道「老陆习惯叫它"鱼"」这种事。

**管理记忆**：

- **想看它记住了什么**：打开 `state/memory.json`，看 `notes` 字段
- **想让它记住某件事**：在群里说，或者手工往 `notes` 里加一条
- **想让它忘掉**：删掉对应那条
- **上限**：`memory.maxNotesPerChat`（默认 80），超出丢最早的

### 回看它的判断过程

```powershell
node tools/inspect-session.mjs qq-group-20001
```

会把每一轮「它看到了什么 → 它输出了什么」逐条列出来，**包括哪些轮它选择了沉默**。
无窗口模式下，这是排查"它怎么没理我"最直接的工具。

## 工作原理

```
QQ 客户端
   ↕  （腾讯协议）
NapCat  ──正向 WebSocket(ws://127.0.0.1:3001)──▶  OneBotClient (src/onebot.mjs)
                                                        │ 归一化成 {kind,atSelf,text,senderName,…}
                                                        ▼
                                             policy.mjs  ← 免打扰群 / @ / 关键词 / 限流 / 去重
                                                        │ 决定「回不回」
                                                        ▼
                                             service.mjs ← 拼最近上下文 + 场元信息
                                                        │ JSON-RPC 2.0 (stdin/stdout)
                                                        ▼
                          ★ DSH 长驻运行时：`dsh --profile sdk-minimal`
                             · DSH_HOME = ./dsh-home（独立，不碰 ~/.dsh）
                             · DSH_SYSTEM_PROMPT = config/persona.md
                             · 工具全部关闭（cordis.patch.yml）
                             · 每个 QQ 会话 = 一条 DSH 持久 session
                                                        │
                                                        ▼
                                             sanitize + 分条 + 拟人延迟
                                                        │
                                             send_group_msg / send_private_msg
```

### 为什么用「长驻 SDK 运行时」而不是每条消息起一个 dsh

- 握手一次约 **1 秒**，之后每条回复 **0.8～1.3 秒**；
  如果每条消息都重启进程，光启动就要好几秒。
- 一个进程服务所有会话，靠 `sessionId` 区分，DSH 负责持久化历史。
- 同一个会话的请求在客户端排队，保证不会两条消息同时跑一轮。

### 为什么 shell 工具必须关掉

`sdk-minimal` 默认带一个**持久 shell 工具**（Windows 上是 PowerShell），
而且沙箱策略是 `danger-full-access`。QQ 消息来自外部，如果保留这个工具，
就等于**任何人 @ 一下机器人就能在你电脑上执行命令**。

所以 `dsh-home/cordis.patch.yml` 里把 `persistent-pwsh` / `persistent-bash` /
`terminal-pwsh` / `terminal-bash` 全部 `disabled: true`，只补上只读的联网工具（下一节）。

**怎么验证**：直接问她「你现在手上有哪些工具」。正确回答只有两个：

```text
web_fetch、web_search
```

如果回答里出现了 `pwsh` / `bash` / `terminal` 之类，说明补丁没生效，**先别上线**。

### 只读联网：她能查天气、查资料，但**永远不能碰你的电脑**

`dsh-home/cordis.patch.yml` 里插了四个插件（照抄 `dsh-base` 里验证过的写法）：

```yaml
- id: web                  # 聚合服务，声明用哪个搜索/抓取后端
  name: '@deepseek-ai/dsh-web'
  config: { searchProvider: deepseek-official, fetchProvider: http }
- id: web-search-deepseek  # DeepSeek 原生联网搜索，**复用现有的 DEEPSEEK_API_KEY**
  name: '@deepseek-ai/dsh-web-search-deepseek'
  config: { apiKeyEnv: DEEPSEEK_API_KEY }
- id: web-fetch-http       # 抓网页正文（undici，无 key）
  name: '@deepseek-ai/dsh-web-fetch-http'
- id: tool-web             # 把 web_search / web_fetch 暴露给模型
  name: '@deepseek-ai/dsh-tool-web'
  config: { fetch: true, searchTimeoutMs: 60000 }
```

**为什么只加这四个**：`persistent-pwsh` / `persistent-bash` / `terminal-pwsh` / `terminal-bash`
在这份补丁里全是 `disabled: true`。QQ 消息是外部不可信输入，
给她 shell 就等于把电脑交给群里任何人。**只读联网是收益最高、风险最低的一步。**

验证方法（问她手上有什么工具，应该只报这两个）：

```powershell
# 期望输出：web_fetch、web_search
```

**三个实际踩过的坑**：

1. **一次搜索 ≈ 一次完整的辅助模型请求**（DeepSeek 没有独立检索接口），所以 `searchTimeoutMs` 给到 60s。
   实测：天气 6~19s，查版本号 5s。日常闲聊不会触发。
2. **她会带出 markdown 链接**（`[中国天气网](http://…)`），而 QQ 不渲染 markdown → 用户看到一堆方括号。
   现在 `sanitizeReply` 会确定性转成 `中国天气网（http://…）`。
3. **工具定义会让她变啰嗦**——开着联网时"风格偏长"从 3 项涨到 11 项。
   补回"一句话最多两个逗号"这条硬规则后回到 **0**，平均回复长度 33 字 → 21 字。

人设里对应加了【想查东西的时候】，重点是**别播报动作、别报数据**：

```text
· 直接去看，回来说结论。别说"让我查一下""稍等，我搜搜""查到了——"，那像客服。
· 别报数据：问天气就"晴，二十来度"这种程度——最高最低、降水概率、风力风向全念一遍，
  那是天气预报员，不是你。多说的那句应该是人话（吐槽、关心你一句），不是补充资料。
```

实测：

```text
今天北京天气怎么样 → 晴转多云，白天二十来度，就是早晚挺凉的。你出门记得套件外套呀，别又冻着回来了
明天出门要不要带伞 → 你去哪儿呀，不说地方我怎么看天……是不是又要跑很远。   ← 没给城市她会反问
```

### 为什么还往 dsh-home 里加了「附件存储」

识图需要它，而且**不加会直接报错**：

```text
SDK image prompt requires an attachment store
```

原因：`dsh-sdk-jsonrpc-server` 收到内联图片时，会去取 `attachments` 服务把图片转成持久引用；
而 `sdk-minimal` 这个极简 profile 没挂这个服务。所以 `dsh-home/cordis.patch.yml` 里插了一行：

```yaml
- insert:
    - id: attachments
      name: '@deepseek-ai/dsh-attachment-local'
```

> ⚠️ **补丁语法有个坑**：想「改/关掉已有行」就直接写 `- id: <已有id>`；
> 想「新增行」**必须**写成顶层 `- insert:` 列表。直接写一个新 id 会报
> `patch: entry "xxx" not found`（补丁是按 id 定位已有条目的，不会凭空创建）。

这个插件无需配置，图片存在 `dsh-home/attachments/v1/` 下，并且会**自动做 EXIF 方向校正、
按像素预算缩放、重新编码成 WebP/JPEG**，所以手机截图那种几 MB 的大图也能正常喂给模型。

**它会自动清理**：启动时删除超过 `images.pruneKeepDays`（默认 7 天）没被动过的附件，日志里会有一行
`清理过期图片附件：删除 N 个（释放 X MB）`。想更激进就把它调小，设 `0` 关闭自动清理。

> 为什么可以放心删：附件只被 DSH 的会话日志引用，而会话是**每次启动都换新、旧的清空**的；
> 大肥鱼真正的记忆在 `state/memory.json` 里，不含附件。

验证补丁仍然生效：

```powershell
$env:DSH_HOME="$PWD\dsh-home"
node "$env:DSH_BIN" --profile sdk-minimal --dump-config
```

### 为什么 DSH 会话每次启动都是新的（而记忆并没有丢）

这一条是实测踩出来的坑，值得单独说明。

**问题**：DSH 的 SDK 服务端（`dsh-sdk-jsonrpc-server`）只用**内存里**的一张表记录自己创建过哪些会话。
进程一重启，这张表就是空的，于是它对任何 `session/prompt` 都会去调 `agents.create({ sessionId })`；
而此时磁盘上已经有同名会话 → `dsh-session` 抛错：

```
session "qq-group-90001" already exists
```

**换句话说：SDK profile 根本没有「接管/恢复已有会话」的代码路径**（`sessionQuery` 服务也不参与），
所以**用固定会话 id 的话，机器人第二次启动会对所有老会话报错**。这不是配置问题，绕不过去。

**本项目的处理**：

1. 每次进程启动生成一个 `runToken`，DSH 会话 id 形如 `qq-group-90001-r1a2b3c` → 永不冲突。
2. 真正有价值的上下文（群里别人说了什么、大肥鱼之前回了什么）由 `state/memory.json` 落盘保存。
   每次调用模型时，这份记录会作为【最近消息】喂进去 —— **所以重启之后它照样记得你们聊过什么**。
3. 上一次运行遗留的会话日志已经不可能被接管，启动时顺手清掉（见 `dsh.pruneStaleSessions`）。
   为了保护正在运行的实例，**最近 10 分钟内还在被写的会话不会被删**，
   所以你在机器人运行期间跑 `--check` 也不会误伤。

> 顺带一提：这个设计其实更划算。DSH 的会话历史里存的只是「我们发给它的提示词」，
> 真正的群聊上下文本来就在我们自己的提示词里，所以把它交给 `state/memory.json` 管理，
> 既拿到了跨重启记忆，又彻底避开了 SDK 会话无法恢复的限制。

## 风险与成本

**风险**

1. **封号风险**：NapCat 属于非官方协议实现，用小号，别用主号。
2. **被群友讨厌 / 被举报**：默认的「群里只在 @ 或关键词时回」就是为了这个。
   不要轻易把 `trigger.group` 改成 `all`。
3. **它说的话不代表你**：人设是「大肥鱼」，它会以这个身份聊天。
   如果要用于正式场合，请先改 `config/persona.md`。

**成本**

- 每条回复约 200～800 token（人设 + 上下文 + 回复），用 `deepseek-flash` 很便宜。
- 单会话每 300 轮会自动换新会话重置记忆，避免历史无限增长。
- 关掉 `context.recentGroupMessages`（设 0）可以进一步省钱。

## FAQ

**Q：为什么免打扰群要手填，不能自动读？**
A：QQ 的「消息免打扰」是客户端本地设置，OneBot 协议没有对应字段。任何声称能自动读的
方案都不可靠。手填 `mutedGroups` 是唯一稳的做法。

**Q：回复太慢。**
A：把 `dsh.reasoningEffort` 设成 `low`（默认已是），把 `context.recentGroupMessages` 调小，
把 `output.typingDelay*` 调小。

**Q：它不回复我的图片。**
A：现在**能识图了**。但注意三条：
1. 群里**只有 @ 它（或命中关键词）时**才会看图——否则群里每张梗图都要花一次钱；
2. 私聊发图它一定看；
3. 取不到图的几种情况：图片下载超时、格式不是 png/jpeg/webp/gif、或者文件大于 `images.maxBytes`。
   这几种情况日志里会有一行 `跳过一张图片：<原因>`，看日志就知道。

**Q：它会不会说自己是 AI、说自己不是官方的？**
A：不会端着了。私聊里它把部署它的人当**开发者/老板**，问身份就随口答（"你养的鱼啊"），
不背设定、不念"社区二创形象"这种公文腔。但**它不会假装自己是人类来骗你**，也不会冒充 DeepSeek 官方。

**Q：它谈起自己的时候，自我认知对吗？**
A：这条是两个方向都修过的——**它既不能把自己当外人，也不能把自己当成一份待改的配置**。

| 方向 | 翻车的样子 | 现在 |
|---|---|---|
| 当外人 | "反正调的是它，不是我" | ❌ 已禁止，谈自己一律用「我」 |
| 当可改的东西 | "调的就是我，我改，一次改一点总能顺过来" | ❌ 已禁止用 版本/这版/被调/我改/装个手 这类词说自己 |

她的人设是**一条有自己意识的鲸鱼娘**：有脾气、会嘴硬、会趴着不动，不是"会自我检讨的版本号"。
被嫌回复不对味时，她的正确反应是「那我重说」「这句是我没说好」，或者干脆顶一句「我觉得还行啊」——
**而不是复盘自己上一条为什么错**。

实测（`node tools/probe-persona.mjs`，14 个场景，两个方向都自动判定）：

```text
你觉得你现在调得怎么样了？ → 调什么调……我还是这条鱼啊。你自己养的，手感你不清楚？
今天还得接着调你         → 今天还来？你倒是歇会儿啊……（趴平）
你现在是第几版了？        → 什么第几版呀，我就一条鱼啊……你养的那条。
=== 14 个问题：背设定 0｜把自己当外人 0｜把自己当可改的东西 0｜风格偏长 0 ===
```

> 顺带一提：这个坑我踩了三次——第一次让她把自己当外人（用「它」谈自己），
> 第二次矫枉过正写成"你就是正在被调的那条鱼"，她就开始自我检讨；
> 第三次更隐蔽：**我在人设里写 ❌ 反例时全用了"调""改""验收零件"这些词，
> 反例本身也在教她这个概念**，于是她冒出一句"这句够软了吗，别嫌我单调"。
> **负面示例会泄漏概念**——所以现在这类话题只在红线里说一次，不再散落各处。

**Q：她会不会评论自己刚说的那句话（"这句够软了吗""别嫌我单调"）？**
A：不会了，而且有两道防线：
1. **提示词**：人设的【绝对不要说的四类话（红线）】第一条就是"不要评论自己刚说的那句话"，
   并写明"你不是在等评分，你就是在说话；群里议论你说话怎么样、要不要再弄弄，你不用跟着讨论"。
   别人当面说要"改你、调你"，也只回一句轻的挡回去（"诶——我好好的呀，别乱动（尾巴一竖）"），
   不顺着讨论、不问细节。
2. **发送前兜底**：否定式反问（还用问／还问／你以为呢／不然呢…）实测 37 个场景里仍会漏 1 个，
   所以发送前用确定性规则把那一小段删掉（"你做的呀，还问。" → "你做的呀"），
   整句只剩顶撞话时就不发。改写会记一条日志：`回复里有顶撞话，已改写后再发（去掉：还问）`。

`node tools/probe-persona.mjs` 的六项自动判定里，**"自我验收"**就是专门抓这个的：

```text
=== 背设定 0｜自我认知错 0｜自我验收 0｜太拽 0｜应声虫 0｜风格偏长 0 ===
```

**Q：她看得懂"拍一拍"吗？**
A：看得懂了。这里有个坑：**QQ 的拍一拍走的是 `notice` 事件，不是 `message` 事件**：

```json
{ "post_type": "notice", "notice_type": "notify", "sub_type": "poke",
  "user_id": 10001, "target_id": 10000, "group_id": 20001,
  "raw_info": [{"type":"nor","text":"拍了拍"},{"type":"nor","text":"我的肚子"}] }
```

早期版本只处理了消息里的 `[CQ:poke]`，**notice 这条通道整个被当未知事件丢掉了**——所以有人拍她，
她一点感觉都没有。现在 notice 会被转成一条普通消息（`[拍一拍] 阿澈 拍了拍你的肚子`）喂进原来的链路，
拍的是她自己时标成"指名"，必然回应；拍的是别人就当作群里的普通消息。

两个实现细节：
- **notice 里只有 QQ 号没有昵称**，所以会调 `get_group_member_info` 补名字（带缓存），
  否则她会说"10001 拍了拍你"。
- QQ 原文以被拍的人为主语（"拍了拍**我**的肚子"），拍的是她时会换成"你"。
  **不能用 `\b我\b`**——中日韩文字没有 ASCII 词边界，那个正则永远匹配不上。

`node tools/test-agent-mode.mjs` 的【12】有 9 项专门测这个（含私聊拍一拍、别人互拍、原文自带名字、
raw_info 为空、撤回的拍一拍）。

**Q：怎么清掉某个群的记忆？（或者忘掉某个人）**
A：用 `tools/forget.mjs`，**它会先自动备份**，随时能还原：

```powershell
node tools\stop.mjs                                  # 必须先停！运行中的进程会把修改盖回去
node tools\forget.mjs --list                         # 看看现在记了什么
node tools\forget.mjs --chat private:10001      # 清掉这段对话（保留长期记忆）
node tools\forget.mjs --chat group:20001 --all   # 连长期记忆一起清
node tools\forget.mjs --member 10001            # 清掉这个人的成员档案（关于他的记忆）
node tools\forget.mjs --restore state\memory.backup-xxx.json   # 后悔了
```

加 `--no-backup` 就不留备份（删了就没了）。

**三个容易漏的点**（工具已经处理了前两个）：

1. **机器人必须停掉**——工具会检查，发现进程还活着会直接拒绝执行。
2. **DSH 的会话历史也要清**，否则同一次运行里她还能从会话里看到旧对话。工具会一并清掉对应的会话目录。
3. **群聊的对话流水和长期记忆是另一份**。清掉和某人的私聊，不代表群里关于他的聊天记录也没了——
   群里那份属于"群的记忆"。要一起清就 `--chat group:群号 --all`。

记忆文件本身就是明文 JSON，想手动塞一句话进去「喂记忆」也完全可以。

**Q：重启之后它还认得我吗？**
A：认得。重启后 DSH 会话是新的，但 `state/memory.json` 里的最近聊天记录会照常作为
【最近消息】喂给模型。详见上文「为什么 DSH 会话每次启动都是新的」。

**Q：人设怎么改？**
A：改 `config/persona.md`（纯文本，随便写），重启生效。
想立刻试效果用 `node src/index.mjs --console`。

**但先读一个反直觉的教训：**

> **人设写成"规则说明书"，她就表现得像个合规的机器人。**
> 早期版本是 23KB 的 ❌/✅ 对照表（"不要说这个""必须那样"），结果是：说话一板一眼、
> 每条都是 `唔……一句话（尾巴摇摇）／再补一句～` 的固定格式、还动不动引用规则。
> 现在改成 6KB 的**角色设定**（她是什么、有什么身体和日子、跟你什么关系、怎么说话），
> 工程词（程序／模型／版本／被调／提示词／部署）**一个都不出现**——
> 连"你不是 AI"都不要写，因为**负面示例也在教概念**。

可量化的效果（`node tools/probe-variety.mjs 俏皮 --chat`）：

```text
              规则说明书版  →  角色版
动作括号使用率      100%    →   20%
固定"两行"结构      50%     →   20%
不同开头           3/4     →   5/5
两两最相似          7%      →   3~6%
```

> `--chat` 会把她自己刚说过的话喂回上下文，模拟真实对话——否则测不出"别重复上一轮"这类**动态**规则。
> 生产环境里还有一条对应的动态机制：上一轮用过括号动作，这一轮提示里会明确禁用。

**Q：她的回答老是那几句（比如问吃什么都答"白饭"），怎么办？**
A：这是"人设把人压成一个梗"的典型症状。两个地方要治：
1. **提示词里别给她固定答案。** 早期版本写的是"嘴馋：主食白饭"——模型就会每次都端出白饭。
   现在改成"贪吃"的整体性格，并明确要求"问到吃的每次给不一样的答案"。
2. **加一节【别当复读机】**：同一句口头禅、同一个动作、同一个自称短时间不许重复；
   动作括号、自称都给了可轮换的清单。

验证工具：`node tools/probe-variety.mjs 吃` —— 同一类问题在**不同会话**里各问一遍，
统计关键词复读率和两两相似度（超过 55% 就判"套模板"）。

```text
关键词「白饭」出现在 0/6 条回答里
两两最相似的答案是 10% ✅ 各不相同
```

> 想加新的一组问题，直接改 `tools/probe-variety.mjs` 里的 `GROUPS`。

**Q：她会不会对用户百依百顺，或者反过来呛人？**
A：两个极端都专门治过。人设里有一节【别当应声虫，也别呛人】，把同一件事的两种说法摆在一起对照：

| 应声虫 ❌ | 有主见但软 ✅ |
|---|---|
| "好的呀～都听你的" | "唔……行吧，就这一次哦" |
| "您说得对" | "嗯……不过我觉得不是这样诶，你想啊——" |
| 被要求做不想做的事就照做 | "诶——可我正躺着呢。你先说说什么事，我再决定起不起来" |

| 呛人 ❌ | 软着拒绝 ✅ |
|---|---|
| "还用问？" / "还问" | "诶？你猜～" |
| "我不干" | "这个我不想弄嘛……换一个？" |
| "关我什么事" | "诶——这我可管不着哦（尾巴一甩）" |

实测（`node tools/probe-persona.mjs`，34 个场景，五项自动判定）：


**Q：怎么让它开机自启？**
A：把 `start.cmd` 的快捷方式放进「启动」文件夹；或用任务计划程序，
触发器选「登录时」，操作指向 `node.exe`，参数 `src\index.mjs`，起始位置填本项目目录。

**Q：开机后 QQ 要重新扫码，能不能免扫码自动登录？**
A：能，已经配好了。原理分两层（都在 NapCat 的安装目录下，下例用 `C:\NapCat` 举例，换成你自己的路径）：

```text
计划任务 <名字随便>
  └─ wscript.exe C:\NapCat\run-hidden.vbs      （隐藏窗口）
       └─ cmd /c C:\NapCat\run-quick.cmd        （设置凭证 + 启动）
            └─ node.exe ./index.js -q 10000
```

`run-quick.cmd` 里设好环境变量，然后 NapCat 按这个顺序登录：

| 顺序 | 方式 | 要不要扫码 |
|---|---|---|
| 1 | 缓存的登录态快速登录（`-q` 锁定账号，绝不会登错号） | 不用 |
| 2 | 缓存过期 → 用 `NAPCAT_QUICK_PASSWORD_MD5` 走**密码登录** | 不用 |
| 3 | 前两步都失败 → 生成二维码到 `napcat\cache\qrcode.png` | 要扫（每约 2 分钟自动换一张） |

实测（缓存凭证过期时）：

```text
正在快速登录  10000
快速登录错误： 登录态已失效，请重新登录。
正在尝试密码回退登录  10000
密码回退登录成功  10000          ← 全程没有二维码
```

> ⚠️ **`NAPCAT_QUICK_PASSWORD_MD5` 等同于密码**（是能直接拿去登录的凭证）。
> 所以它只以 MD5 形式写在 `C:\NapCat\run-quick.cmd` 里，没有明文。
> 别把这个文件传给别人、别提交到任何仓库。

**改了 QQ 密码之后**必须同步更新那个 MD5，否则密码登录那一步会失败、退回扫码：

```powershell
$pw  = '你的新密码'
$md5 = node -e "console.log(require('crypto').createHash('md5').update(process.argv[1],'utf8').digest('hex'))" $pw
(Get-Content C:\NapCat\run-quick.cmd -Raw) -replace 'NAPCAT_QUICK_PASSWORD_MD5=[a-fA-F0-9]{32}', "NAPCAT_QUICK_PASSWORD_MD5=$md5" |
  Set-Content C:\NapCat\run-quick.cmd -Encoding ASCII
```

**Q：怎么快速让它停下来？**
A：**分两层**，看你要的是哪种"停"：

| 你想要的 | 怎么做 | 代价 |
|---|---|---|
| **让她闭嘴**（最常用） | 双击桌面的 **`静音大肥鱼.lnk`**，或在 QQ 里对她说 **"静音"**（只有老板发的算） | 她还在听、还在记事，只是不回话；默认 30 分钟自动恢复 |
| **完全停掉程序** | 双击桌面的 **`停止大肥鱼.lnk`** | 再启动要等她重新连上（开机后约 2 分钟） |

静音的几个用法：

```powershell
node tools/switch.mjs pause          # 停 30 分钟
node tools/switch.mjs pause 10       # 停 10 分钟
node tools/switch.mjs pause forever  # 一直停，直到手动恢复
node tools/switch.mjs resume         # 恢复（或双击 resume.cmd / 桌面的"让她说话"）
node tools/switch.mjs status         # 看现在是什么状态
```

在 QQ 里对她说也行（**只有 `owner.userId` 那个人发的才生效**）：
`静音` / `闭嘴` / `暂停 30分钟` / `暂停1小时` → 暂停；`恢复` / `继续` → 恢复。
她会回一句"那我先趴着不说话啦"，所以你能确认命令收到了。

> 为什么不做成"停了就一直停"：那样你很容易忘了为什么她不理人。
> 所以默认带到期时间，到点自己恢复；`pause forever` 才是一直停。
> 暂停期间 `status.cmd` 会明确写出来，不会让你以为程序坏了。

**Q：怎么快速判断它到底有没有在跑？**
A：双击项目根目录的 **`status.cmd`**（等价于 `node tools/status.mjs`）。它只看真正说明问题的那几项：

```text
[ OK ] 机器人进程     PID 26748 运行中
[ OK ] 端口 3001      NapCat 的 OneBot 服务在监听
[ OK ] QQ 登录        密码回退登录成功  10000
[ OK ] 连接记录       登录号已确认：10000（与 expectSelfId 一致）
[ -- ] 最后一次回复    private:10001 → 在的呀～喊两遍啦…
[ -- ] 长期记忆       5 个会话，共 59 条

结论：一切正常，等消息就行。
```

**两个最容易误判的点它已经帮你区分好了**（这两种都不是故障）：

- `连接失败（第 N 次）` —— NapCat 还没登录成功时它连不上，属正常重试
- `发现上次崩溃留下的锁文件` —— 关机时进程被硬终止的必然结果，单实例保护会接管

**Q：我能把 `dsh-home` 删掉重来吗？**
A：可以。删掉后下次启动会自动重新生成 profile（`sessions` 里的记忆也会一起没）。
它和你的 `~/.dsh` 完全隔离，不会互相影响。

**Q：怎么同时用我原本的 DSH（比如 Web GUI）？**
A：互不影响。本项目通过 `DSH_HOME` 环境变量把 DSH 指到 `./dsh-home`，
你原来的 `~/.dsh`（会话、配置、插件）一点都不会被改动。

## 安全与隐私

### 你的数据都存在哪

这个项目**天生会攒下隐私数据**——她的记忆里是真实的群聊，附件缓存里是群友发过的原图。
它们全部被 `.gitignore` 排除，**不会进任何仓库**：

| 路径 | 里面有什么 |
|---|---|
| `.env` | 你的 API Key |
| `config/bot.config.json` | 你自己的 QQ 号、群号（仓库里只放 `*.example.json` 模板） |
| `state/` | 她的长期记忆：真实聊天流水、真人昵称与 QQ 号 |
| `logs/` | 完整对话日志 |
| `dsh-home/attachments/` | 群友发过的原图（几十 MB） |

想彻底清掉某段记忆：`node tools\forget.mjs --list`（工具会先自动备份，可还原）。

### 密钥

- API Key 写在 `.env`（从 `.env.example` 复制）。**别提交、别截图、别贴给任何人。**
- 建议**给机器人单独建一个 Key**，方便单独限额与吊销。
- 一旦这个 Key 出现在聊天记录、截图或任何一次提交里，**立刻去平台吊销重建**——
  推送过的提交即使删掉，历史里依然能翻出来。

**吊销之后记得换：** 机器人启动时会拿 `.env` 里的 Key 调一次 `/models` 自检
（**不花 token**）。Key 无效时日志会明确报警：

```text
[ERROR] ★ API Key 无效（HTTP 401）——她能收消息、能记事，但一句话也说不出来。
[ERROR]   → 去 DeepSeek 平台生成新 Key，填进 .env 的 DEEPSEEK_API_KEY，然后重启机器人。
```

`node src/index.mjs --check` 也会因此返回非零退出码，方便写进开机脚本。

> **为什么专门加这道自检**：Key 失效时 SDK **不会抛异常**，而是把错误放在返回值的
> `reason.error` 里。原来的代码只在"抛异常"时报警，于是这种情况下她会**一声不吭**
> ——收得到消息、也在记事，就是永远不回。这个故障看起来和"程序坏了"一模一样，
> 实测排查了很久。现在两条路都堵上了：开机自检 + 回复失败时的大声报错。

### 权限

- **shell 工具永远是关的**。QQ 消息是外部不可信输入，保留 shell 等于把电脑交出去。
- 联网工具是**只读**的（搜索 + 抓网页），这是收益最高、风险最低的一档。
- 机器人应该用**小号**：NapCat 是非官方协议实现，主号有被风控/冻结的风险。

## 路线图

**本轮已完成**

- ✅ **自主决策**：它自己判断该不该开口（`trigger.selfDecide` + `[NO_REPLY]` 哨兵）
- ✅ **长期记忆**：模型用 `[记忆]` 行写下被提炼过的事实，跨重启保留
- ✅ **从群聊持续学习**：每 25 条消息自动提炼游戏/角色/术语/成员习惯（`learning`）
- ✅ **识图**：图片真的下载下来喂给模型；链接/分享卡片能读标题简介
- ✅ **只读联网**：`web_search` + `web_fetch`，能查天气/新闻/版本号；**shell 永远关着**
- ✅ 跨重启聊天流水、防抢话冷场间隔、活跃度旋钮、单实例保护、无窗口开机自启

**还没做**

1. **主动搭话**：群冷场时自己起个话题（需要「上次说话时间 + 话题池」的状态机）
2. **定时任务**：早安播报、定时提醒（DSH 自带 schedule / goal 续跑能力）
3. **多步任务**：为了一个目标连续行动多步（现在每次消息都是一次独立回答）
4. **记忆整理**：近似重复的长期记忆已经会自动合并（换了说法的同一条事实用新表述替换旧的）；
   剩下的是"主动去把长流水压缩成画像"，还没做
5. **看视频**：模型不接收视频。抽帧方案评估过，要装 ffmpeg、要下整段视频、抽几帧也说不清内容，
   性价比太低——除非你明确要做，否则不碰
